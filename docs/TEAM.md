# Familiar — team coordination

Team name: **Familiar**  
Theme: **Looks Familiar · Sounds Familiar · Feels Familiar**  
Repository scope: **the whole hackathon**, not only proximity alerts.

## Suggested roles

| Area | Owner | Deliverable |
|---|---|---|
| Device SDK integration | Teammate working with the glasses | One real green HUD message using verified official SDK |
| Camera / other inputs | To be agreed | Confirm real SDK APIs; log what works and what doesn't |
| Proximity-attention prototype | Teammate working on proximity | Browser-simulated scenarios, decision logic, tests |
| UX and audio | To be agreed | Concise readable messages and intentional tone behavior |
| Integration / demo | Shared | End-to-end demonstration, issue tracking, submission |
| Conversation Starter + Social Navigator | User (browser prototype) | Independent social.html demo; no hardware dependency |

## Work sequence

1. Define the minimum on-device win: display one message.
2. Split hardware API discovery from browser prototype work.
3. Test using tabletop or simulated data, never near traffic or platform edges.
4. Commit in separate feature branches and use pull requests.
5. Rehearse a short demo; be explicit about simulated vs verified features.
